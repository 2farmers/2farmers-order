# 倆口田前後台更新步驟

此版本已完成本機模擬測試，尚未部署至 Google Apps Script，也未合併 GitHub 正式分支。沒有向正式後台送出測試訂單；手機畫面與 Google 實際執行環境仍待驗證。

## 1. 先建立獨立測試環境

僅在原 Apps Script 專案新增部署，不會隔離試算表資料；這份程式使用 `getActiveSpreadsheet()`，同專案的部署仍會寫入同一份綁定試算表。不要把新增部署當成測試資料隔離。

1. 先建立一份測試試算表，保留必要表頭，使用測試商品與虛構的收件資訊；商品主檔、訂單總表、出貨明細、記帳總表、合作夥伴設定的結構需對應正式表。
2. 從測試試算表開啟「擴充功能 → Apps Script」，確認是另一個 Apps Script 專案，再放入本資料夾的 `Code.gs`。
3. 只在測試專案建立網頁應用程式部署，把其網址放入測試前台的 `gasUrl`。正式前台的 `gasUrl` 和正式 Apps Script 原始碼先保持原狀。
4. 在測試環境驗證商品載入、一般售價、分溫層送出、訂單編號、收據金額，以及將狀態改成「已確認」後的明細、記帳和庫存。確認只有測試試算表新增資料。
5. 瀏覽器畫面與上述實際串接驗證通過，再進行以下正式更新。

## 2. 測試通過後，更新正式 Apps Script 後台

1. 在目前的訂單試算表，開啟「擴充功能 → Apps Script」。
2. 先把原本的 `Code.gs` 另存備份到電腦，記下目前使用的部署版本。不要在同一個 Apps Script 專案增加一份同名函式的備份，避免重複定義。
3. 開啟本資料夾的 `Code.gs`，複製全部內容，替換原本 `Code.gs` 的全部程式，再儲存。不要直接執行 `doPost` 或 `onEdit`，它們需要事件參數。
4. 點右上角「部署 → 管理部署作業」，選目前訂購頁使用的網頁應用程式部署，點鉛筆編輯。
5. 版本選「新版本」，填入例如「接單鎖定、後台金額及確認重試修正」，再按「部署」。保留既有執行身分與存取設定。
6. 更新原部署可保留原 `/exec` 網址。完成後告知助手，以便核對並接續處理前台。不要把新建部署的不同網址直接當成已更新原網站。

Google 官方說明：[更新既有部署](https://developers.google.com/apps-script/concepts/deployments#edit_a_versioned_deployment)。儲存程式會立即影響綁定試算表的 `onEdit`，而對外 `/exec` 則需更新部署版本。

## 3. 更新正式前台

後台更新後，再檢查並合併 GitHub 修改提案 #1；合併 `main` 才會觸發現有 GitHub Pages 發布流程。這份後台仍接受原前台格式，因此可以先更新後台。

驗收時要核對：常溫／低溫各自運費、兩筆訂單的收件資料、後台訂單編號、收據與 LINE 文字是否和訂單總表一致。實際送出測試訂單會寫入試算表，請優先在副本環境測試；正式表中的測試訂單應明確標註並人工處理，勿混入出貨。

## 經營流程與新增欄位

- 常溫及低溫一次選購、分兩次確認送出，收件資料只填一次。每筆都有自己的訂單編號及運費；不是後台自動拆成兩筆。
- 保留原本「新訂單不預留庫存，改為已確認才扣庫存」的規則。取消也仍不自動回補庫存，需依原本作業方式人工核對。
- 訂單總表會自動增加「確認處理」欄；出貨明細、記帳總表會自動增加「明細鍵」欄。原有表格與欄位保留，這些欄位供中斷後續作使用，不要手動清空。
- 若確認中斷，該列狀態回到「新訂單」，狀態儲存格會留下原因註記。排除問題後再選「已確認」，程式會接續寫入，避免重複明細、記帳及扣庫存。
- 若某筆確認尚未完成，先處理它再確認其他訂單。處理中不要修改該筆商品 JSON、金額、收件資料或相關商品的 soldQty；程式偵測到衝突時會要求人工核對。
- 舊訂單若已經有明細／記帳，但沒有新版確認紀錄，不能據此判斷以前是否已扣庫存。重新選「已確認」時會提示人工核對，不會盲目再扣一次。已完成的舊訂單不需要重新確認。
- 本版是以鎖定和處理紀錄協助重試，Google 試算表跨表寫入仍非資料庫交易。若試算表被手動修改、欄位被刪除或權限不足，可能需要人工排除。

## 已執行的測試

在專案目錄執行：

```sh
node tests/backend.cjs
node tests/checkout-unit.cjs
```

測試涵蓋後台重新計價與配送溫層、同商品數量合併後檢查庫存、重複訂單、鎖定逾時、寫入後回應失敗、明細／記帳／庫存各階段中斷後續作、重複確認、人工庫存衝突，以及前台收據／LINE 使用後台金額。

測試採記憶體內的 Sheets、Lock 與 DOM 替身，未驗證 Google 配額、真實觸發器執行時間或手機 LINE 開啟情況。另附 `tests/checkout.cjs` 為尚未執行的瀏覽器測試。

## 回復方式

若需回復，先停止確認處理尚未完成的訂單，核對「確認處理」非 done 的紀錄；不要清空紀錄後重新確認。Apps Script 原始碼可用電腦備份還原，對外部署可切回先前版本；前台可還原 GitHub 合併提交。恢復程式不會撤銷已寫入的訂單、記帳或庫存，這些資料仍需核對。
