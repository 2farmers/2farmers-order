# 倆口田共耕搬遷版本

目前是待部署及實機測試的版本，尚未切換會員入口。

## 架構

`cofarm/` 是獨立的靜態網站目錄。保留原 HTML 的內容、手機排版、會員 ID 與查詢碼流程，將 google.script.run 改為 HTTPS POST JSON 呼叫。請求以 text/plain 傳送並跟隨 Google ContentService 的重新導向；不把會員碼放在網址或瀏覽器儲存中。後台沿用原試算表及既有驗證函式。

`apps-script/CoFarmApi.gs` 是新增的 Apps Script 檔案，僅開放網站需要的函式；不開放後台管理函式。付款回報需要取得新申請的驗證憑證，綁定申請編號及類型，有效七天；前台只在當次頁面記憶體保留。離開頁面後若需要付款回報，請聯絡倆口田提供申請編號。API 不自動重送寫入要求，避免網路中斷時重複新增資料。

現有 Code.gs、Index.html 和試算表資料不需要替換。

## 第一步：更新共耕 Apps Script（先做這一步）

1. 開啟「倆口田｜共耕會員後台」試算表，選「擴充功能 → Apps Script」。
2. 按檔案旁的「＋」，新增「指令碼」，命名 `CoFarmApi`。
3. 將 `apps-script/CoFarmApi.gs` 的全部內容貼入並儲存。保留原本的 Code.gs 及 Index.html。
4. 選「部署 → 管理部署作業」，找到現在共耕系統使用的網頁應用程式，按鉛筆編輯。
5. 版本選「新版本」，更新現有部署。沿用目前「執行身分：我」及訪客可存取的部署設定；若設定不同，先回報目前選項再處理。
6. 使用目前同一個 /exec 網址。若 Google 產生不同網址，提供新網址以更新 `cofarm/config.js`。

新增的檔案定義 doPost；目前提供的原程式沒有 doPost。若你在貼入前已另外新增過 doPost，請先整合，不能同時保留兩個同名入口。

## 第二步：部署新前台

目前程式位於 `cofarm-migration` 分支，待後台更新後再合併到 main。
現有儲存庫已用於訂購網站，所以先在其中新增獨立 cofarm 目錄，不需建立新儲存庫；訂購首頁的 index.html 不變。
部署完成後，預定測試入口為 `https://2farmers.github.io/2farmers-order/cofarm/`。
這是預定路徑，尚未驗證上線；不能現在發給會員。

## 第三步：測試再切換

- Chrome 與 Safari：首頁、兩個入口、查詢碼正確與錯誤時的回應。
- 既有會員：共耕紀錄、果樹紀錄、田間近況、蔬果甘特圖。
- 申請：蔬果與果樹選項、既有會員資料帶入、阻擋重複申請與額滿方案。
- 寫入測試使用你明確指定的測試會員／申請資料；不要用真實會員建立測試訂單。
- 付款回報：同頁面送出申請後回報；錯誤憑證不能更新其他申請。
- 會員留言、提問回覆、活動報名與取消。
- 必須使用手機 Facebook App 點擊新連結實測首頁、登入及資料載入；桌面瀏覽器通過不代表 Facebook 通過。

通過後才更新粉專、官 LINE 及會員通知，並在旧入口加入下列提示。不要在尚未測試完成時宣告搬遷完成。

按鈕須使用測試通過的正式網址，target="_top"。舊頁若在 Facebook 完全無法載入，提示也無法顯示，所以對外連結仍須改成新入口。

## 驗證與回復

本機檢查：`node tests/api.test.cjs`。
測試涵蓋允許清單、錯誤會員碼交由原驗證處理、付款憑證綁定、回呼隔離、錯誤處理及禁止自動重送寫入。
尚未實測 Apps Script ContentService 的跨來源回應、真實試算表、部署權限與 Facebook 內建瀏覽器。

切換前可继续使用旧入口。若新版有問題，先恢復對外原連結；必要時將 Apps Script 部署切回前一版本。請保留原始程式備份。
